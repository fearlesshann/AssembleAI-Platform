# T4 · 应用注册与发布控制面

> **For agentic workers:** 按已授权 SPEC 执行。模型 / schema / 校验、数据库 / 仓储、HTTP / 验收独立分工；主线程集成，不重复请求常规实现选择。

**Goal:** 交付有权限、并发控制和事务审计的应用注册、审核、版本及租户启停 API。

**Architecture:** 全局 Application / Release 与租户活动版本指针分离。应用开发 / 发布审核角色使用独立全局表，绝不从租户业务角色推导；发布物只能匹配部署方预配置的精确映射。每次命令在 PostgreSQL 事务中检查状态与 revision，成功变更和审计一并提交。

**Tech Stack:** .NET 10、System.Text.Json 严格清单校验、JSON Schema 2020-12、Npgsql / PostgreSQL 17、现有 OIDC / CSRF / tenant session；不新增第三方包或容器依赖。

**Spec:** SPEC I.manifest / I.registry / I.audit，T1 D2，V1 / V3 / V4 / V7 / V12 / V15 / V16 / V17 / V20。

## 规则与契约

- 写入 Manifest 包含原七字段，status 必须 draft；新增 schemaVersion=1、frontendArtifact={version,sha256}、backendVersion，category / description。appId / service 为小写稳定 slug；版本采用无前导零的 major.minor.patch，入口精确 `/apps/{appId}/{frontendArtifact.version}/`。拒绝未知 / 重复字段、URL / 编码路径、重复权限和超限文本；声明不授予权限。
- 部署配置 `Registry:FrontendArtifacts` 精确列出 AppId / Version / Entry / Sha256；`Registry:BackendBindings` 精确列出 Service / Version / Audience / Destination。浏览器不能登记服务地址。发布时验证受控部署映射；配置不是实际健康探测，正式运行前健康 / 兼容检查及服务发现接入仍属 T5 / T14。
- 迁移 4：global registry operators（developer / reviewer）、applications、application_releases、tenant_applications、registry_audit。无预置管理员。全局角色按当前 iss/sub + enabled user/role 查询。
- Developer 创建自己的 app、编辑 draft、submit；reviewer 可 reject / publish / disable / enable，publish 时不能批准自己的提交。第一次发布后内容不可变；disabled 只能恢复同一已批准内容。新内容必须新 version。
- Release revision 从 1 开始；新建 expectedRevision=0，其他命令需精确匹配，否则 409。更新同一 app 的操作串行锁定，租户指针变化亦检查 revision；没有部分发布物更新。
- 租户配置写入要求已选且明确匹配的 tenant，fresh `registry:manage` + resourceType=application / resourceId=appId / tenantWide grant。初次 expectedRevision=0；启用 / 切换只接受 published release；全局 disabled 时仍允许停止现有租户关系。配置 enabled 与实际 available 分开，后者还要求当前 release published。
- 写接口固定 Origin + CSRF；GET 不变更。正常用户没有全局管理能力；全局 reviewer 不获得租户数据权限。
- 每个已识别操作者的状态变更尝试记录 actorId / tenantId / appId / version / action / result / requestId / time；成功变更与审计同一事务，审计失败回滚。审计不保存 Manifest 全文、token 或部署目标。未认证 / 无有效平台用户请求在边界拒绝。
- 所有响应 no-store；401 / 403 / 404 / 409 / 400 与安全 503 区分。无 Runtime / 动态代理 / 公共目录假实现；T5/T6 再将不可变 release 接入运行与门户。

## API

全局管理 `/api/platform/v1/registry/apps`：

- GET `/{appId}/releases`：owner developer / reviewer 查看，最多 100 条；GET `/{appId}/releases/{version}` 查看单版本。
- PUT `/{appId}/releases/{version}`：`{expectedRevision,manifest}` 新建或编辑草稿，路径必须与 manifest 一致。
- POST `/{appId}/releases/{version}/transitions`：`{expectedRevision,action}`，action=submit/reject/publish/disable/enable。

租户配置 `/api/platform/v1/tenants/{tenantId}/applications/{appId}`：

- GET：有同一管理权限时返回配置或 404。
- PUT：`{expectedRevision,releaseVersion,enabled}` 更新独立租户指针，返回配置与 availability。
