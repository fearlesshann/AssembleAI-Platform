# T5 · 正式应用网关与运行生命周期

按已授权 SPEC T5 推进。采用现有 YARP 2.3 IHttpForwarder，每次请求读取已发布组合 / 租户状态，再使用部署者配置的服务版本地址；不新增依赖。固定静态代理不能表达租户版本指针；全量共享路由表会把个体运行授权混入全局路由，因此选择每次决策后直接转发。该选择是本轮实现决定。

## 契约与边界

- 关联 I.gateway / I.registry / I.identity / I.audit，V4,V6,V8,V12,V14–V18,V20,V25；实现复核补充 V29，调用预算不可延长。
- POST `/api/platform/v1/tenants/{tenantId}/applications/{appId}/releases/{version}/runs`：Cookie + Origin / CSRF + 已选同一 tenant，要求租户当前活动版本、全局已发布和 Manifest 全部入口权限。先按可信配置检查后端 health 响应的 service/version/protocolVersion，再在事务中复核创建运行租约。返回 runId、固定版本入口与失效时间，不返回内部凭据或服务地址。
- 应用调用 `/api/apps/{appId}/releases/{version}/{**operation}`：需 X-Run-ID、明确 X-Tenant-ID 和同一服务端 BFF 会话；header 只表示意图。操作只允许受控 Gateway Operations 中的精确 method/path/entry permission；query 和 JSON body 是业务参数，不能改变目标。POST 同样 Origin / CSRF；GET 无正文，不代理任意路径或升级协议。
- 租约默认 15 分钟；租户活动版本切换后旧租约最多排空 120 秒，后续来回切换不能延长期限；不能新建旧版本运行。显式停用永久撤销既有租约，重新启用不恢复。每次调用及在途检查都实时核验当前授权 / 会话 / 状态。
- 会话引用由 ITicketStore 成功读取时写内部 feature，网关不得从客户端 header 构造引用。周期检查直接重新读取 SessionStore，不能使用同请求缓存的 AuthenticateAsync 假装发现退出。
- 默认每 2 秒复核，单次复核预算 3 秒；失效或查询失败即取消，因此正常调度下发现时限最多约 5 秒。调用总长 300 秒，首个下游响应头 10 秒，I/O 空闲 30 秒；同时受租约 / 排空 / BFF 原到期时间约束。取消传到真实 HTTP 下游；依赖不响应取消的业务进程不能被宣称强制终止。
- 单实例按 tenant/user 并发 4、全局并发 64、每分钟 60、无队列；分区最多 10000，饱和拒绝。这是进程级上限，多副本全局配额归后续部署；不能宣称分布式限流。
- HTTP 请求和响应使用 header 白名单。禁止传 Cookie / 调用方 Authorization / 任意身份头；生成新的 requestId 和 RS256 内部凭据。下游禁止 Set-Cookie、Location、CORS、鉴权头进入平台源；固定 no-store。不跟随重定向、不使用系统代理、不重试业务请求。
- SSE 为 UTF-8 `delta` / `complete` / `error` 事件，增量到达即转发；业务失败应发送 error，只有 complete 表示成功终结。网络 EOF / 超时 / 撤权中断而无 complete 视为失败，网关不伪造 complete。转发前错误返回安全 Problem；响应开始后不能保证再写合法错误帧。
- 数据库 migration 5 保存租约与调用记录。调用前持久化 running，失败则不访问下游；结束写 HTTP 结果 / 传输结果 / 时长，不保存 query、body、凭据或目标。结束审计失败保留 running 并结构化报警，不重试业务、不宣称已撤销交付给客户端的响应。业务完成与传输完成分开。

## 实施与验证

1. 先红测匿名 / 禁用路由；补 Gateway options、可信操作表、路由与 YARP transformer，严格参数与大小限制。
2. 并行实现 LiveBffSession、PG runtime / call store 与 migration 5、有界 admission；根线程集成。
3. 真实 OIDC + Kestrel + 下游签名验证测试：当前版本、身份 / 租户 / 会话绑定、权限 / 停用 / 退出撤销、升级排空、错误状态、请求头与响应头隔离、首段不缓冲、取消与超时、限流。
4. 隔离原生 PostgreSQL验证租约生命周期、切换 / 回滚不复活、审计与权限撤销；Core 全量回归。任何缺陷记录 §B 并考虑 §V。
5. 同步 SPEC / 接入与验证文档，仅在完成验收后标记 T5 完成并提交推送现有分支。

YARP 能力边界参考 [Direct forwarding](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/yarp/direct-forwarding?view=aspnetcore-10.0)；调用取消 / 空闲时限配置参考 [HTTP client configuration](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/yarp/http-client-config?view=aspnetcore-10.0)。
